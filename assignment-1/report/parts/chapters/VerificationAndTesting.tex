\section{Verification and Testing}

The project combines JUnit tests on the production code with Java PathFinder
(JPF) exploration of a reduced synchronization protocol.

\subsection{JUnit tests}

The Maven suite checks deterministic physics, collisions, pocketing, FIFO
commands, concurrent submissions, failures, snapshots, shutdown, and view
input. Running \texttt{mvn test} completed with \textbf{158 tests, 0 failures,
and 0 errors}. Both JPF models were executed in Docker.

\subsection{JPF verification}

Two small harnesses model the coordination protocol without full physics,
Swing, timers, or large collections. \texttt{ThreadedMiniHarness} represents
the platform-thread design, while \texttt{TaskBasedMiniHarness} represents the
executor-based one. Both use the shared \texttt{MinimalProtocolState}.

The configurations use depth-first search, \texttt{JenkinsStateSet},
partial-order reduction, and a depth limit of 40. They were executed with
\texttt{run\_jpf.py --docker --model both}. The runner compiles for Java 11 and
requires \texttt{no errors detected} without a \texttt{[SEVERE]} diagnostic.

\subsection{Verified properties, results, and limits}

The searches verify exclusive board ownership, command draining before snapshot
publication, worker completion before commit, resource release, final
termination, and absence of deadlock.

Both searches completed without deadlock or assertion failure:

Both maximum depths remain below 40, so the bound did not truncate either
search. The threaded state space is larger because its worker can interleave
earlier than the task created in the executor model.

The result covers every schedule represented by these bounded harnesses. It
does not prove numerical physics, full \texttt{ExecutorService} behavior,
Swing responsiveness, performance, or arbitrary workloads; these aspects are
covered separately by production tests and benchmarks.
