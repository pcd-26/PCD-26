\section{Introduction}

This project implements the second part of Assignment 4: a distributed
Tic-Tac-Toe application in which one player creates a named room and another
player joins it later. The required communication mechanism is Java RMI, so
the final system must expose remote objects, support network transparency, and
remain correct under concurrent access.

Although Tic-Tac-Toe is a very small game from the algorithmic point of view,
the distributed version introduces a clear systems problem. The application
must coordinate remote discovery, room creation, per-match state ownership,
turn validation, and client notifications while keeping the protocol small and
predictable.

The adopted solution uses one registry process, one server process, and one or
more client processes. The server owns the authoritative state of every active
match; clients only invoke remote operations and render immutable snapshots.
This keeps the distributed boundaries explicit and places the concurrency
control exactly where the shared mutable state lives.
