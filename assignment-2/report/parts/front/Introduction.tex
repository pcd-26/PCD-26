\section{Introduction}

Assignment 2 asks for an asynchronous library, \texttt{FSStatLib}, that scans a
directory recursively and returns a report with two main values:

\begin{itemize}[leftmargin=*]
  \item the total number of regular files found in the directory tree;
  \item the distribution of file sizes in \texttt{numberOfBands + 1} bands,
  where the range from zero to \texttt{maximumFileSizeBytes} is divided into
  \texttt{numberOfBands} bands and the last band counts files larger than
  \texttt{maximumFileSizeBytes}.
\end{itemize}

The project provides three implementations of the same behaviour:

\begin{itemize}[leftmargin=*]
  \item a Virtual Threads version;
  \item a Reactive version based on RxJava;
  \item an Event-Loop version based on Vert.x.
\end{itemize}

The three versions are not simple wrappers around a shared scanner. They are
implemented separately in order to preserve the programming discipline of each
paradigm: imperative asynchronous code for virtual threads, stream-based
composition for RxJava, and callback-driven asynchronous I/O for Vert.x.

The repository also contains a command-line interface and a Swing GUI. The GUI
implements the optional interactive extension: it can start a scan, receive
progressive updates, and cancel a running computation. A JUnit suite checks
correctness, robustness, and cross-implementation consistency on deterministic
filesystem fixtures.
